# Meta Harness

Meta Harness allows building Agent Harnesses from pieces. It helps to run primarily async agents that are harnessed with a specific model, tools, skills and a sandbox environment.

It is not meant to be useful without some coding, you have to write the agent itself in the end and deploy. That is part of the fun.

## Tech Stack

- Language: Go + HTML + REST API (JSON)
- Repo: Monorepo

## Libraries

For the Go HTTP server (stack from [this blog post](https://blainsmith.com/articles/building-go-apis-with-huma-slqc-and-goose/), with SQLite instead of Postgres):

- [Huma](https://huma.rocks) — typed HTTP operations + auto-generated OpenAPI spec
- [sqlc](https://sqlc.dev) — type-safe Go from plain SQL queries
- [Goose](https://github.com/pressly/goose) — plain-SQL schema migrations
- [modernc.org/sqlite](https://pkg.go.dev/modernc.org/sqlite) — pure-Go SQLite driver (no CGO)

## Layout

```
cmd/server/main.go        HTTP server: opens SQLite, runs migrations, wires Huma handlers
sql/migrations/*.sql      goose migrations (also the schema source of truth for sqlc)
sql/queries/*.sql         sqlc query definitions
sql/migrations.go         embeds migrations so the server can self-migrate on startup
db/                       generated by sqlc (checked in) — DO NOT EDIT by hand
sqlc.yaml                 sqlc config (engine: sqlite)
Makefile                  generate / migrate / run targets
```

## Getting started

```sh
make tools     # install the sqlc + goose CLIs into your GOBIN (one-time)
make run       # sqlc generate, then go run ./cmd/server
```

The server listens on `:8080`, runs migrations on startup, and serves interactive
API docs at http://localhost:8080/docs (spec at `/openapi.json`).

Dev loop: add a migration → add a query → `make generate` → wire a Huma handler.
